# iOS 端到端验收清单

本文件定义独立 iOS App 的完成标准。模拟器、单元测试和通用 iOS 构建均不能替代真机证据。

## 测试设备

每轮真机验收记录以下信息：

- iPhone 型号
- iOS 版本与构建号
- App 构建号和 Git commit
- 网络类型（Wi-Fi / 蜂窝）
- 导入配置类型和节点协议（凭据不得写入日志）

## 首次安装

- [ ] App 可在真实 iPhone 上通过开发签名安装并启动。
- [ ] 用户首次允许添加 VPN 配置后，配置出现在系统 VPN 列表。
- [ ] 每台设备生成独立 CA；私钥不可导出到 App 容器外。
- [ ] 用户完成描述文件安装和根证书完全信任后，App 能确认准备状态。
- [ ] 拒绝任一首次授权时 App 不崩溃、不阻断普通网络，并能继续引导重试。

## 配置导入与代理

- [ ] 从文件导入 sing-box JSON。
- [ ] 从文件导入目标 Shadowrocket 配置并展示兼容性报告。
- [ ] 从订阅 URL 导入并更新配置。
- [ ] 支持粘贴文本和二维码导入。
- [ ] 导入失败不覆盖上一个可用配置。
- [ ] 节点凭据保存在 Keychain，诊断日志无明文凭据。
- [ ] 代理、规则和直连策略在 Wi-Fi 与蜂窝网络均符合配置。
- [ ] VPN 重载/重启后仍使用最后确认的配置和节点。

## 地图与坐标

- [ ] 地图点击/长按选点、搜索、当前位置、收藏和历史记录可用。
- [ ] 苹果地图、高德短链和坐标文本在设备端完成解析。
- [ ] 中国大陆 GCJ-02 到 WGS84 转换通过固定样例和真机回看验证。
- [ ] App 不需要自建 Worker、数据库或 WLOC 后台。

## 设置虚拟位置

- [ ] 选择目标坐标后 App 自动保存坐标并重载内置 VPN。
- [ ] App 明确引导用户手动关闭、开启系统定位服务。
- [ ] 用户返回 App 后流程自动继续，不需要再操作 VPN。
- [ ] App 验证定位结果与目标坐标的距离在设定误差内。
- [ ] Wi-Fi 定位和基站定位响应中的可修改位置均被替换。
- [ ] 强 GPS、缓存或系统拒绝采用 WLOC 时明确显示“未生效”，不得误报成功。

## 恢复真实位置

- [ ] 点击恢复后坐标进入透传模式并自动重载 VPN。
- [ ] 用户手动关闭、开启定位服务后，真实定位恢复。
- [ ] 最终状态为定位服务开启、内置 VPN 开启、普通代理继续工作。
- [ ] App 验证恢复结果；无法验证时不得显示成功。

## 稳定性与故障保护

- [ ] 锁屏 30 分钟后代理和 WLOC 仍可用。
- [ ] Wi-Fi 与蜂窝双向切换后自动恢复。
- [ ] VPN Extension 被系统终止后能够恢复，或给出可操作的失败状态。
- [ ] 配置损坏、证书缺失、上游节点离线时普通网络不会被静默黑洞。
- [ ] 连续设置/恢复 20 次无崩溃、无状态串线、无坐标泄漏。
- [ ] 重启手机后的配置、收藏和透传状态符合重启前设置。

## 完成证据

完成通知必须附带：

1. 单元测试、集成测试和 Xcode Archive 结果。
2. 真机型号、系统版本和逐项验收记录。
3. 设置与恢复的屏幕录制或时间戳日志。
4. 导入配置兼容性报告。
5. 所有遗留问题；只要存在影响上述条目的问题，就不能宣称完成。

## 真机诊断证据采集

每次“确定定位”和“恢复真实定位”完成后，都执行以下步骤：

1. 打开“代理与 VPN > 真机诊断”，点击“刷新诊断”。
2. 确认页面显示本次 Packet Tunnel 会话、最后补丁时间、响应次数，以及定位/Wi-Fi/基站修改计数。
3. 点击“生成无凭据诊断文件”并保存 JSON；文件包含 App/设备/iOS 版本、VPN 状态、配置格式、目标与回读坐标、距离阈值和补丁计数，不含节点地址、用户名、密码或配置正文。
4. 将 JSON 与同一轮操作的屏幕录制、定位回读结果和设备/iOS 信息放在同一证据目录。
5. 设置虚拟位置时，若响应次数为 0、最后补丁时间为空，或需要覆盖的定位/Wi-Fi/基站计数始终为 0，只能记录为“未取得补丁证据”，不得据此勾选成功。
6. 恢复真实位置采用透传模式，修改计数为 0 属正常；此时至少应看到“真实定位透传”、新的最后补丁时间和大于 0 的响应次数，再结合真实定位回读判定恢复结果。

诊断 JSON 只证明 Packet Tunnel 观察并处理过目标响应，不能替代真实 iPhone 的定位回读、Wi-Fi/蜂窝网络实测或录屏。
